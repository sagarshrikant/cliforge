# cliforge 0.4.0

Declarative validation and a richer, fully-typed schema — all opt-in behind
`@schema cliforge v2`. **Existing `v1` schemas are unaffected: generated output
is byte-for-byte identical to 0.3.x.** The generator accepts both `v1` and `v2`.

## Highlights

- **Unit-aware quantity types, for real.** A `duration`, `bytes`, or
  `frequency` option now generates a typed `struct { value; unit }`, a unit
  enum, and a conversion helper. `--timeout=30s` keeps the unit and
  `<prefix>_duration_to_ns()` returns `30000000000` — no more hand-written
  conversion glue.
- **`units [ … ]`** restricts the accepted unit suffixes for a quantity, shows
  them in `--help`, and rejects an out-of-list default at generate time.
- **`on-error = exit | warn`** — a per-option (and `meta`-default) policy for
  invalid input. `exit` fails the parse; `warn` reports, keeps the default (or
  clamps), and continues. The generated code never calls `exit()` itself.
- **Range enforcement** — `in lo..hi` / `max =` on integer options now emit
  runtime bounds checks that honour the `on-error` policy.
- **Typed fields inside compound records** — a `period : duration` or
  `sched : sched_t` field in a `name = { … }` compound gets real typed storage
  and parsing, for single and repeatable (`multiple`) records.
- **Cleaner generated enums** — constants are now fully upper-cased
  (`CC_VERBOSITY_QUIET`).

All generated code still compiles cleanly under **C89, C99, and C11** with zero
warnings, uses no heap and no third-party libraries, and the test suite is green
at **92 tests**.

## Install

**apt (recommended):**

```sh
curl -fsSL https://shrikant-sagar.github.io/cliforge/cliforge-archive-keyring.gpg \
  | sudo tee /usr/share/keyrings/cliforge-archive-keyring.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/cliforge-archive-keyring.gpg] https://shrikant-sagar.github.io/cliforge stable main" \
  | sudo tee /etc/apt/sources.list.d/cliforge.list
sudo apt update && sudo apt install cliforge
```

**Direct `.deb`** (attached below): `sudo apt install ./cliforge_0.4.0_amd64.deb`

**From source:** `cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build && sudo cmake --install build`

## Upgrading

Nothing to change — existing v1 schemas generate identical code. To adopt the
new features, bump a schema's first line to `@schema cliforge v2`. See
`docs/spec/SPEC.md` §27 for the v2 additions and the full
[CHANGELOG](../../CHANGELOG.md).

## Notes

- Negative range lower bounds and quantity ranges are not yet enforced; `ratio`
  remains a scalar; inline choice inside a compound is intentionally a guiding
  error (declare a named choice type instead).
- The VSCode schema extension (0.3.0) now understands v2 syntax —
  highlighting, completion, hover, and diagnostics for `on-error` and
  `units [ … ]`.
