# cliforge 0.4.0 — design & implementation plan

Status legend: **DONE** (implemented + green), **TODO** (designed, not yet built).

0.4.0 is a minor release. New *schema syntax* is gated behind `@schema cliforge v2`;
`v1` schemas keep their exact 0.3.x behaviour. The generator accepts both `v1`
and `v2`. Range *enforcement* is also v2-only, so existing v1 schemas that
declared a range (and relied on it being ignored) do not change behaviour.

Each feature ships with: SPEC.md update, unit test(s), system test(s), and a
demonstration in the `calctool` example (kept domain-neutral).

---

## 1. Enum constant casing — DONE

Generated enum members are now fully upper-cased:
`CC_VERBOSITY_QUIET` (was `CC_verbosity_QUIET`). Fix in `cf_gen.c` `enum_val()`:
the type-name segment is upper-cased alongside the prefix and member. The
`typedef` name itself stays lower-case (`cc_verbosity` / `cc_verbosity_t`).
Verified: parser references the same constants; 88 tests pass.

## Foundation: `@schema cliforge v2` — DONE

`cf_parse.c` now reads `vN` generically and stores `schema_version`. Feature
gating below keys off `out->schema_version >= 2`.

## 2. Inline choice inside a compound field — TODO

**Goal:** allow `sched : (a, b, c) = b` as a compound field (today only a
*named* choice works inside a compound; inline is rejected).

**Schema (v2):**
```
thread = {
    prio  : sint8
    sched : (other, fifo, rr) = rr
}
```

**Changes:**
- `cf_ast.h` `cf_field_t`: add inline-choice storage
  `char members[CF_MAX_MEMBERS][CF_MAX_IDENT_LEN]; unsigned int nmembers;`.
- `cf_parse.c` compound-field parser: when the field type begins with `(`,
  parse the member list into the field (mirror the inline-choice path already
  used for options).
- `cf_gen.c`: emit a per-field enum (named `PREFIX_RECORD_FIELD`) and store the
  field as that enum — same treatment as a named choice field (see item 7).

**Tests:** parse unit test (field carries members); system compile test.

## 3. `on-error = exit | warn` — TODO (v2)

**Goal:** per-option policy when a value fails validation; default `exit`.
A `meta { on-error = ... }` sets the project default.

**Semantics (keeps generated code passive — never calls `exit()`):**
- `exit`  → on a bad value the parse function reports the error and returns
  non-zero (the caller decides to terminate; this is today's model).
- `warn`  → print a warning to stderr, keep the option's default (or last good
  value), and continue parsing; the parse function still returns 0.

**Schema (v2):**
```
meta { on-error = exit }            // project default (optional)
option precision { type = uint8 in 0..16  on-error = warn }
```

**Changes:**
- `cf_ast.h`: add `cf_on_error_t on_error;` to `cf_option_t` and a default to
  `cf_meta_t` (`char on_error[CF_MAX_IDENT_LEN];` or an enum).
- `cf_lex.c`: `on-error` is `ident '-' ident`; already lexes as tokens — handle
  in the option-qualifier parser (no new keyword token needed if we match text).
- `cf_parse.c`: parse the qualifier in the option loop + the meta default.
- `cf_gen.c`: thread the resolved policy into the per-option validation
  branches (used by item 5 too): on violation, either set error+return or warn+
  fall back to default.

**Error message format:** `error: --mode: got 'x', allowed: a|b|c`
and for ranges `error: --prio: got 200, allowed 0..16`.

**Tests:** system test — a bad value with `exit` returns non-zero; with `warn`
returns 0, prints to stderr, and keeps the default.

## 4. Numeric range enforcement — TODO (v2)

**Goal:** emit the runtime checks for ranges already declarable
(`uint8 in 0..16`, `max = N`). Today they parse but are not enforced.

**Changes:** `cf_gen.c` integer/quantity parse sites: after `strtol/strtoul`,
compare against `range_lo`/`range_hi` (already in `cf_type_expr_t`) and apply
the `on-error` policy. Gate emission on `schema_version >= 2`.

**Tests:** system test — in-range passes; out-of-range hits the policy.

## 5. `units [ ... ]` restrict + display — TODO (v2)

**Goal:** restrict accepted units for a quantity and surface them in `--help`.

**Schema (v2):**
```
period : duration units [us, ms, s] = 10ms
deadline : duration units [ms, s] = 250ms
```

**Changes:**
- `cf_ast.h`: add allowed-units list to `cf_type_expr_t`
  (`char units[CF_MAX_MEMBERS][8]; unsigned int nunits;`).
- `cf_lex.c`/`cf_parse.c`: parse `units [ ... ]` after a quantity type.
- Generate-time check: the default's unit must be in the list (else schema
  error). The parser rejects an out-of-list unit at runtime per `on-error`.
- `cf_gen.c` help printer: append `(units: us|ms|s)` to the option's help line.

**Tests:** unit test (units parsed); system test (disallowed unit rejected;
help lists units); negative generate-time test (default unit not in list).

## 6. Typed quantity / choice fields inside compounds — TODO (v2)

**Goal:** fix the 0.3.x limitation where `bytes`/`duration`/choice fields inside
a compound are emitted as plain `int`. They should generate the same typed
storage as top-level options.

**Changes (`cf_gen.c`, the compound struct + parse emitters):**
- `duration`/`bytes`/`frequency`/`ratio` field → emit the `{value, unit}`
  struct (`struct cc_duration` etc.) and wire the conversion helpers.
- choice field → emit the field as the generated enum type (not `int`).
- compound sub-option parser → fill these typed fields from the `key=value`
  tokens (suffix parsing for quantities, member match for choice).

This is the largest item; it touches compound storage layout and the
`key=value` field parser. Do it last and re-run the C89/C99/C11 compile tests.

**Tests:** system compile test asserting `struct ..._thread` carries
`struct cc_duration period;` and the enum type; parse test for `period=500us`
inside a record.

## Example plan (calctool, domain-neutral)

Demonstrate the features without leaning on any specific application domain:
- a named choice field inside a compound (`item 2`),
- a quantity option with `units [...]` and a range (`items 4, 5`),
- an option with `on-error = warn` and one defaulting to `exit` (`item 3`),
- a compound option with a `duration` field to show typed compound storage
  (`item 6`).

## Sequencing

Built in this order, each green before the next: **(done)** foundation + casing
→ 2 inline-choice-in-compound → 3 on-error → 4 range → 5 units → 6 typed
compound fields → SPEC + CHANGELOG + example + full C89/C99/C11 test sweep.
